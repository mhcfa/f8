## Proposal

### What

Implement the foundational specification data structures, Serde models, and semantic validation rules for Finx financial models, supporting project manifests (`finx.json`) and modular table definitions (`tables/*.json`) as defined in [`docs/dsl/spec-format.md`](../../docs/dsl/spec-format.md).

### Why

The Finx compiler requires an unambiguous, strongly typed internal representation of incoming model definitions before performing grid expansion, cycle detection, or Excel layout emission. Establishing these structs with two-stage validation ensures invalid models are rejected early with structured, actionable diagnostics.

### Scope

- **In-scope**:
  - Core identifier newtypes: `TableId`, `RowId`, `ColId`, `ColGroupId`, `RowGroupId`.
  - Project manifest structs: `ProjectManifest`, `SheetSpec`, `FreezePanes`.
  - Table specification structs: `TableSpec`, `ColumnGroup`, `RowGroup`, `RowGroupChild`, `RowSpec`, `FormatPreset`, `ValueLiteral`, `MatchArmSpec`.
  - Parsed match selector: `MatchSelector`.
  - Deterministic storage using `IndexMap` for preserving key/ordering fidelity.
  - Two-stage ingestion: Serde deserialization followed by semantic validation (`TableSpec::validate` and `ProjectManifest::validate`).
  - Structured domain error types using `thiserror`: `ModelError`.
  - Unit tests verifying JSON serialization/deserialization and validation against sample specs from [`docs/dsl/spec-format.md`](../../docs/dsl/spec-format.md).
- **Out-of-scope**:
  - Formula expression parsing into AST nodes (reserved for Phase 2: `formula-parser`).
  - Cell IR grid expansion and coordinate allocation (reserved for Phase 3: `grid-expansion`).
  - Disk I/O directory traversals and multi-file loading helpers (can be built on top once data types and validation are verified).

### What Changes

- Update `Cargo.toml` with dependencies: `serde`, `serde_json`, `thiserror`, `indexmap`.
- Introduce `src/model/` module hierarchy:
  - `src/model/mod.rs`: Module exports and public surface.
  - `src/model/id.rs`: Strongly typed identifier wrappers.
  - `src/model/format.rs`: `FormatPreset` enum with snake_case serialization.
  - `src/model/manifest.rs`: `ProjectManifest` and `SheetSpec`.
  - `src/model/table.rs`: `TableSpec`, `RowSpec`, groups, payloads, and selectors.
  - `src/model/error.rs`: `ModelError` diagnostic hierarchy.
- Convert `src/main.rs` or create `src/lib.rs` to expose the library target.

### Capabilities

- **New capabilities**:
  - Ability to deserialize and validate `finx.json` manifests.
  - Ability to deserialize and validate standalone `tables/<id>.json` specifications.
  - Structured compile errors pointing to invalid match partitioning, mismatched array dimensions, non-contiguous groups, and duplicate IDs.
- **Modified capabilities**: None (initial implementation).

## Design

### Goals

1. **Deterministic representation**: Use `IndexMap` / `IndexSet` to preserve declared order of columns, rows, and match partitions.
2. **Clear diagnostics**: Decouple JSON syntax errors from model invariant violations via two-stage validation.
3. **Zero production panics**: Use `Result` and `thiserror` without `.unwrap()` or `.expect()`.
4. **Strict schema compliance**: Faithfully mirror the specification format and invariants documented in [`docs/dsl/spec-format.md`](../../docs/dsl/spec-format.md).

### Invariants

1. **Mutually exclusive row payload**: A row definition must contain exactly one calculation payload: `value`, `expr`, or `match`.
2. **Mutually exclusive match arm payload**: Each match arm must specify exactly one of `value` or `expr`.
3. **Dimension match**: Literal array length must equal the number of targeted columns (`len(value) == len(target_columns)`).
4. **Disjoint & exhaustive partitioning**: Every column in `table.columns` must be matched by exactly one arm in `row.match`. Overlapping or uncovered columns produce a validation error.
5. **Contiguous & disjoint column groups**: Every column group must span a contiguous sub-slice of `table.columns` with no overlapping memberships.
6. **Contiguous & disjoint row groups**: Descendant rows of every row group must form a contiguous sub-slice of `table.rows` with no duplicate memberships across groups.
7. **Semantic format presets**: Only predefined format presets are allowed (`currency`, `currency_total`, `percentage`, `multiple`, `integer`, `decimal`, `basis_points`, `date`, `text`).

### Decisions

- **Two-stage ingestion (Serde + Validation)**:
  - *Choice*: Deserialize into raw specification structures (`RawRowSpec`, `RawTableSpec` or fields with `Option`), then call `.validate()` to verify domain invariants.
  - *Rationale*: Serde errors for untagged enums across multiple fields can be confusing. Two-stage validation gives precise contextual error messages (e.g. `"Row 'revenue' in table 'IncomeStatement': missing match arm for column '2025E'"`).
  - *Alternatives considered*: Strict custom Serde visitor (rejected due to complex error reporting and higher implementation complexity).
- **Identifier newtypes**:
  - *Choice*: Create simple tuple structs `TableId(pub String)`, `RowId(pub String)`, `ColId(pub String)`, `ColGroupId(pub String)`, `RowGroupId(pub String)` deriving `Deref<Target = str>`, `Display`, `Serialize`, `Deserialize`, `PartialEq`, `Eq`, `Hash`, `Clone`, `Debug`.
  - *Rationale*: Completely prevents accidental identifier transposition while retaining ergonomic `&str` slicing and formatting.
  - *Alternatives considered*: Plain `String` aliases (rejected due to lack of type safety); interned string pool (deferred to later optimization phases if profiling warrants).

### Data Contracts

#### Core Data Structures

| Struct / Enum | Responsibilities | Key Fields |
| :--- | :--- | :--- |
| `TableId` | Programmatic table identifier | `pub String` |
| `RowId` | Programmatic row identifier | `pub String` |
| `ColId` | Programmatic column identifier | `pub String` |
| `ColGroupId` | Column group identifier | `pub String` |
| `RowGroupId` | Row group identifier | `pub String` |
| `FormatPreset` | Standard semantic formatting preset | `Currency`, `CurrencyTotal`, `Percentage`, `Multiple`, `Integer`, `Decimal`, `BasisPoints`, `Date`, `Text` |
| `ProjectManifest` | Root manifest schema (`finx.json`) | `model_name: String`, `theme: String`, `sheets: Vec<SheetSpec>` |
| `SheetSpec` | Worksheet visual container | `name: String`, `tab_color: Option<String>`, `freeze_panes: Option<FreezePanes>`, `show_gridlines: bool`, `tables: Vec<PathBuf>` |
| `TableSpec` | Standalone table calculation spec | `id: TableId`, `title: String`, `columns: Vec<ColId>`, `column_groups: Vec<ColumnGroup>`, `row_groups: Vec<RowGroup>`, `rows: Vec<RowSpec>` |
| `ColumnGroup` | Contiguous column group | `id: ColGroupId`, `label: String`, `columns: Vec<ColId>` |
| `RowGroup` | Hierarchical row section | `id: RowGroupId`, `label: String`, `children: Vec<RowGroupChild>` |
| `RowGroupChild` | Child item in row group | `Row(RowId)` or `Group(RowGroup)` |
| `RowSpec` | Row definition | `id: RowId`, `label: String`, `format: Option<FormatPreset>`, `note: Option<String>`, `source: Option<serde_json::Value>`, payload |
| `ValueLiteral` | Explicit literal cell value | `Number(f64)`, `String(String)`, `Null` |
| `MatchArmSpec` | Match arm calculation | `value: Option<Vec<ValueLiteral>>`, `expr: Option<String>`, `note: Option<String>`, `source: Option<serde_json::Value>` |
| `MatchSelector` | Parsed match selector key | `Single(ColId)`, `Range { start: ColId, end: ColId }`, `Group(ColGroupId)` |

#### Validation Error Diagnostics

```rust
#[derive(Debug, thiserror::Error, PartialEq)]
pub enum ModelError {
    #[error("Table '{table}': row '{row}' must have exactly one of 'value', 'expr', or 'match'")]
    MutuallyExclusivePayload { table: TableId, row: RowId },

    #[error("Table '{table}': row '{row}' arm '{arm}' must have exactly one of 'value' or 'expr'")]
    MutuallyExclusiveArmPayload { table: TableId, row: RowId, arm: String },

    #[error("Table '{table}': row '{row}' expected {expected} values, found {actual}")]
    DimensionMismatch { table: TableId, row: RowId, expected: usize, actual: usize },

    #[error("Table '{table}': row '{row}' match partitioning is not exhaustive, missing columns: {missing:?}")]
    UncoveredColumns { table: TableId, row: RowId, missing: Vec<ColId> },

    #[error("Table '{table}': row '{row}' column '{column}' is matched by multiple arms")]
    OverlappingMatchArm { table: TableId, row: RowId, column: ColId },

    #[error("Table '{table}': column group '{group}' columns are not a contiguous sub-slice")]
    NonContiguousColumnGroup { table: TableId, group: ColGroupId },

    #[error("Table '{table}': column '{column}' belongs to multiple column groups")]
    OverlappingColumnGroup { table: TableId, column: ColId },

    #[error("Table '{table}': row group '{group}' descendant rows are not a contiguous sub-slice")]
    NonContiguousRowGroup { table: TableId, group: RowGroupId },

    #[error("Table '{table}': duplicate row id '{row}'")]
    DuplicateRowId { table: TableId, row: RowId },

    #[error("Table '{table}': duplicate column id '{column}'")]
    DuplicateColumnId { table: TableId, column: ColId },
}
```

### Risks & Trade-offs

- **Risk**: Recursive `RowGroup` validation can be tricky if cycles exist in deserialized data.
  - *Mitigation*: Track visited group IDs during validation to explicitly reject cyclic hierarchies.
- **Trade-off**: Deserializing floats (`f64`) vs `rust_decimal::Decimal`.
  - *Mitigation*: Excel stores IEEE 754 floating point numbers natively. `f64` matches Excel precision and standard financial modeling outputs, keeping memory low and avoiding decimal conversions before Excel emission.

### Acceptance Criteria (Given / When / Then)

- [x] **Scenario 1: Deserialize valid `finx.json` manifest**
  - **Given** a valid JSON project manifest with sheets and freeze panes
  - **When** deserialized with `serde_json::from_str`
  - **Then** produces a valid `ProjectManifest` matching all fields.

- [x] **Scenario 2: Deserialize and validate uniform calculation table**
  - **Given** a JSON table with uniform `expr` rows (e.g. assumptions or simple income statement)
  - **When** deserialized and validated with `TableSpec::validate`
  - **Then** validation succeeds with `Ok(())`.

- [x] **Scenario 3: Reject row with multiple payloads**
  - **Given** a row specifying both `"value": [10]` and `"expr": "Table.x[@]"`
  - **When** validated
  - **Then** returns `Err(ModelError::MutuallyExclusivePayload { .. })`.

- [x] **Scenario 4: Reject non-exhaustive match partitioning**
  - **Given** a table with columns `["2023A", "2024E", "2025E"]` and a row with `match` covering only `["2023A"]`
  - **When** validated
  - **Then** returns `Err(ModelError::UncoveredColumns { .. })` listing the uncovered columns.

- [x] **Scenario 5: Reject overlapping match selectors**
  - **Given** a table with columns `["2023A", "2024E", "2025E"]` and match arms overlapping on `"2024E"`
  - **When** validated
  - **Then** returns `Err(ModelError::OverlappingMatchArm { .. })`.

- [x] **Scenario 6: Reject mismatched value array length**
  - **Given** a table with 3 columns and a row with `"value": [1.0, 2.0]`
  - **When** validated
  - **Then** returns `Err(ModelError::DimensionMismatch { expected: 3, actual: 2, .. })`.

- [x] **Scenario 7: Reject non-contiguous column and row groups**
  - **Given** a column group referencing non-adjacent column indices
  - **When** validated
  - **Then** returns `Err(ModelError::NonContiguousColumnGroup { .. })`.

- [x] **Scenario 8: Parse and validate complex nested row groups**
  - **Given** a table with hierarchical assets (current and non-current assets)
  - **When** validated
  - **Then** verifies hierarchy contiguity and returns `Ok(())`.
